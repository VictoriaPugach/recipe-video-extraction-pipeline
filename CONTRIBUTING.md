# Как работать над модулем

Работа принимается через Pull Request. Реализуй небольшой проверяемый шаг за раз; не меняй контракт приложения без согласования.

## Первый запуск

```bash
cp .env.example .env
make install
make test
make run
```

Прочитай [README](README.md), [архитектуру](docs/architecture.md) и [схему](docs/data_schema.md). Текущий `501` — ожидаемое поведение заглушки. Не заменяй его заранее заготовленным рецептом под видом результата извлечения.

## Ветки и PR

1. Создай ветку `feature/<краткая-задача>` или `fix/<краткая-задача>` от актуальной основной ветки.
2. Опиши ожидаемое поведение и границы изменения.
3. Реализуй его в соответствующем модуле и добавь тесты публичного поведения в принятом стиле pytest.
4. Запусти `make test`. Отдельно проверь сервис через `/docs` или Postman.
5. Открой PR с описанием результата, командами проверки и известными ограничениями.

В PR укажи:

- Что теперь умеет пользователь или API.
- Какие тесты запускались и с каким результатом.
- Нужны ли новые зависимости, переменные окружения или изменения контракта.
- Как воспроизвести сценарий на разрешенном тестовом видео.
- Какие проверки не выполнялись и почему.

## Проверки и данные

Тесты API с подменой внешних вызовов подтверждают обработку запроса, но не качество STT/OCR/LLM. Для оценки качества нужны реальные видео и вручную проверенная разметка. Требования к данным описаны в [data/input_videos](data/input_videos/README.md).

Обычный CI должен быть воспроизводим без оплачиваемых LLM-запросов и скачивания моделей. Проверки с реальными внешними сервисами запускай отдельно и документируй их результаты. Не добавляй тесты приватных методов: проверяй публичное поведение модулей.

Не коммить `.env`, API-ключи, cookies, персональные данные и файлы без прав на использование. Новые зависимости фиксируй в `requirements.txt`; выбор тяжелых моделей и их требования к ресурсам объясняй в PR.

Успешный CI каркаса не заменяет [Definition of Done](README.md#definition-of-done). Рубрика в [evaluation.md](docs/evaluation.md) — предложение для обсуждения с руководителем, а не утвержденные правила учебного курса.
