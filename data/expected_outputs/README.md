# Примеры и будущие эталоны

`pasta.json`, `omelette.json` и `salad.json` — **синтетические примеры общего Recipe 1.0.0**. Они созданы для проверки формата. Они не извлечены из видео и не сверены с реальными роликами.

Для подготовки эталонного набора:

1. Добавь соответствующие разрешенные MP4 по [инструкции](../input_videos/README.md).
2. Вручную выпиши только сведения, подтвержденные содержимым ролика.
3. Замени синтетический JSON разметкой и укажи проверяемый источник.
4. Проверить JSON командой `.venv/bin/python -m fropti_core_contracts data/expected_outputs/*.json`: она использует `Recipe` 1.0.0. Контрактные тесты дополнительно проверяют те же файлы по JSON Schema. Неизвестные значения сохранять как `null`; не добавлять сведения для заполнения полей.
5. Зафиксируй происхождение видео и проверку разметки в `../input_videos/provenance.md`.

Сравнение выполнять по [метрике из рубрики приёмки](../../docs/evaluation.md#как-считать-совпадение-полей). Поля и правила нормализации согласовать до запуска оценки. Для каждого результата сохранить список пропущенных полей, лишних полей и несовпадающих значений; отдельно отметить сведения, не подтверждённые видео.

Эти же файлы служат примерами границы трёх модулей: video extraction производит объект целиком, cooking planner / batch cooking читает шаги и порции, shopping list — ингредиенты и порции. Потребители не должны переименовывать поля или создавать собственный вариант `Recipe`. Примеры не подтверждают готовность логики планирования или списка покупок.
