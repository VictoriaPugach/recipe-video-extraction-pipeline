Модуль извлечения рецептов из коротких видео для **Fropti — планировщика домашнего питания**. Целевой сценарий: человек загружает видео с устройства или отправляет ссылку на YouTube Shorts, Reels или RuTube, сервис объединяет речь, надписи и кадры в структурированный рецепт, а приложение использует его для планирования питания. Поддержку каждой платформы студент должен реализовать и проверить отдельно.

## О проекте

Fropti помогает ответить на три связанных вопроса: **что приготовить, когда готовить и какие продукты понадобятся**. В продуктовом замысле приложение учитывает продукты дома, предпочтения, ограничения и график готовки. Видео с интересным блюдом становится частью этого сценария: рецепт нужно не просто сохранить, а превратить в данные, которые можно использовать в меню и списке покупок.

## Что уже есть и что предстоит сделать

| Сейчас в каркасе | Задача студента |
| --- | --- |
| FastAPI, CLI, Docker и команды запуска | Скачать видео и проверить его длительность |
| Прием видеофайла и проверка формата входного URL | Реализовать извлечение кадров, STT и OCR |
| Явный черновой контракт и режим общего пакета | Объединить сигналы через LLM и валидировать результат |
| Тесты границ API и синтетические JSON | Добавить реальные видео и проверить качество извлечения |
| Документы, пример клиента и коллекция Postman | Подключить согласованную версию `fropti-core-contracts` |

**Реальный пайплайн пока не реализован.** Корректный URL и непустой файл в пределах лимита приводят к `501 pipeline_not_implemented`. Каркас принимает файлы, но не скачивает видео по ссылке и не вызывает модели. Проверка лимита в 180 секунд предусмотрена в пайплайне, но начинает работать с реальным видео после реализации определения длительности. Проходящие тесты каркаса не доказывают качество извлечения.

## Quick Start

Нужны Git и Docker с Compose. Для локального запуска — Python 3.10+.

```bash
git clone https://github.com/VictoriaPugach/recipe-video-extraction-pipeline.git
cd recipe-video-extraction-pipeline
cp .env.example .env
docker compose up --build
```

Альтернатива без Docker, после клонирования и создания `.env`:

```bash
make install
make run
```

Открой [Swagger UI](http://localhost:8000/docs). Самый простой способ отправить видео: раскрой **POST /extract/upload → Try it out → выбери файл → Execute**. Пока распознавание не реализовано, ожидается `501`.

Проверка доступности:

```bash
curl http://localhost:8000/health
```

В режиме по умолчанию:

```json
{"status": "ok", "contract_mode": "draft"}
```

Это проверка доступности HTTP-сервиса, а не готовности распознавания. База данных для этого stateless MVP не нужна. Docker-образ включает `ffmpeg`; при локальной реализации обработки медиа установи его отдельно. Whisper, OCR и клиент LLM пока не выбраны и не включены в обязательные зависимости каркаса.

## Пример запроса и ответа

**Видео с устройства** отправляется как файл:

```bash
curl -i -X POST http://localhost:8000/extract/upload \
  -F 'file=@data/input_videos/pasta.mp4'
```

`pasta.mp4` — имя будущего тестового видео: добавь свой файл или укажи путь к нему. В репозитории MP4 пока нет. Файл должен быть непустым и не больше **100 МиБ**. Проверку формата медиа и реальной длительности студент реализует в пайплайне.

**Видео по ссылке** отправляется как JSON:

```bash
curl -i -X POST http://localhost:8000/extract \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://www.youtube.com/shorts/EXAMPLE_ID"}'
```

`EXAMPLE_ID` — плейсхолдер, а не тестовое видео. Текущий ответ каркаса — `501 Not Implemented`:

```json
{"detail": {"code": "pipeline_not_implemented", "message": "..."}}
```

Ниже **пример будущего `200 OK` в черновой схеме**, а не результат обработки этой ссылки и не подтвержденная схема общего пакета:

```json
{
  "title": "Омлет",
  "servings": 1,
  "ingredients": [
    {"name": "Яйца", "amount": 2, "unit": "шт."},
    {"name": "Соль", "amount": null, "unit": null}
  ],
  "steps": ["Взбейте яйца с солью.", "Приготовьте омлет на сковороде."],
  "source_url": "https://www.youtube.com/shorts/EXAMPLE_ID"
}
```

Оба способа используют один пайплайн и возвращают `Recipe`. Для локального файла в черновой схеме `source_url` равен `null`: ссылка не выдумывается.

Лимит — **180 секунд включительно**. Видео длиннее лимита должно давать `400 video_too_long`; неверный JSON или URL, отсутствие файла — `422`; пустой файл — `400 empty_file`, файл больше 100 МиБ — `413 file_too_large`. Полный контракт: [API reference](docs/api_reference.md).

CLI использует тот же пайплайн:

```bash
.venv/bin/python -m src.main 'https://www.youtube.com/shorts/EXAMPLE_ID'
.venv/bin/python -m src.main --file data/input_videos/pasta.mp4
```

Выбери один источник: URL или `--file`. CLI читает локальный файл напрямую, без HTTP-загрузки. Для обращения к запущенному API есть клиент:

```bash
.venv/bin/python examples/example_client.py --file data/input_videos/pasta.mp4
```

## Контракты данных и мобильная интеграция

Python работает **на сервере**. Мобильное приложение на Flutter или KMP — выбор еще не сделан — обращается к FastAPI по REST. Python, Whisper, OCR и LLM не запускаются нативно на телефоне. Схема API доступна в `/openapi.json`.

Общий источник модели `Recipe` — пакет **`fropti-core-contracts`**, импорт `from fropti_core_contracts.models import Recipe`. [Относительная ссылка на репозиторий контрактов](../fropti-core-contracts) требует проверки: точный URL, версия пакета и его схема пока не предоставлены.

Чтобы каркас запускался до подключения пакета, по умолчанию явно выбран `CONTRACT_MODE=draft`. Это временная локальная модель. Режим `CONTRACT_MODE=shared` требует установки согласованной версии общего пакета и не подменяет его черновой моделью при ошибке импорта. Перед интеграцией нужно обновить зависимости, примеры и тесты по настоящему `Recipe`. Подробнее: [схема данных](docs/data_schema.md).

## С чего начать

1. Запусти сервис, открой `/docs` и получи ожидаемый `501`.
2. Выполни `make test`, затем прочитай [архитектуру](docs/architecture.md).
3. Согласуй общий `Recipe` и три доступных для использования видео. Пока в репозитории только синтетические JSON, а не результаты распознавания.
4. Реализуй определение длительности в `src/downloader.py`. Первым рабочим сценарием сделай отказ для видео длиннее 180 секунд.
5. Собери один сквозной сценарий «локальное видео → Recipe», затем добавляй остальные источники сигналов и платформы.

## Definition of Done

- [ ] Согласована и закреплена версия `fropti-core-contracts`; сервис работает с `CONTRACT_MODE=shared`.
- [ ] Поддержаны URL через `POST /extract` и файл через `POST /extract/upload`; успешный ответ — валидный общий `Recipe`.
- [ ] Локальные файлы проходят тот же пайплайн без скачивания; согласовано представление отсутствующего `source_url` в общем контракте.
- [ ] Проверены пустой файл, превышение 100 МиБ, неподдерживаемое или поврежденное видео и очистка временных файлов.
- [ ] Проверяется длительность: 180 секунд допустимо, больше — `400` до тяжелого распознавания.
- [ ] Реализованы скачивание, аудио/STT, кадры/OCR и объединение через LLM; TODO-заглушки заменены рабочим кодом.
- [ ] Для каждой заявленной платформы есть проверенный сценарий или явно описанное ограничение.
- [ ] Добавлены три видео с разрешенным использованием, источником и ожидаемыми результатами; синтетические примеры не выдаются за эталоны видео.
- [ ] Неизвестные количества не выдумываются; невалидный ответ модели проверяется и обрабатывается с ограниченным числом повторов.
- [ ] Есть таймауты, очистка временных файлов и ограничения загрузки; проверены ошибки внешних сервисов.
- [ ] URL и редиректы не позволяют обращаться к локальным и внутренним адресам сервера.
- [ ] `make test` проходит; тесты проверяют реальный результат и ошибки, а не только моки.
- [ ] Запуск через Docker воспроизводится из чистого клона; README и OpenAPI соответствуют реализации.
- [ ] PR содержит команды проверки, ограничения и примеры полученных рецептов без секретов.
