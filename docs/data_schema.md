# Единый контракт Recipe 1.0.0

## Источник истины

Все три команды используют **один контракт**: [пакет fropti-core-contracts](../packages/fropti-core-contracts/) версии **1.0.0**. Модели определены только в этом пакете, а [JSON Schema](../packages/fropti-core-contracts/schemas/recipe-1.0.0.schema.json) генерируется из них. Пакет устанавливается независимо от FastAPI-сервиса; сейчас он хранится в этом репозитории, без публикации в PyPI или отдельном удалённом репозитории.

```python
from fropti_core_contracts.models import Recipe

recipe = Recipe.model_validate_json(response_text)
payload = recipe.model_dump(mode="json")
```

API, CLI и примеры используют эту же модель. Локальных вариантов Recipe и переключателя режимов нет. JSON Schema — общий формат для Python, Flutter и KMP; Python на телефоне не нужен.

## Recipe

| Поле | JSON-тип | Правило |
| --- | --- | --- |
| `schema_version` | string | Обязательно, строго `"1.0.0"` |
| `title` | string | Обязательно, непустое название |
| `servings` | integer или null | Обязательно; положительное число порций либо `null`, если неизвестно |
| `ingredients` | array of Ingredient | Обязательно; минимум один ингредиент |
| `steps` | array of RecipeStep | Обязательно; минимум один шаг, порядок исполнения задаёт массив |
| `source` | Source | Обязательно; один из трёх вариантов ниже |
| `total_time_minutes` | integer или null | Положительное общее время приготовления в минутах; при отсутствии — `null` |

`servings` относится ко всему рецепту, количества ингредиентов — к этому числу порций. При `servings: null` нельзя обещать корректный пересчёт на другое число порций. `total_time_minutes` не является суммой длительностей шагов: действия могут идти параллельно.

## Ingredient и количество

| Поле | JSON-тип | Правило |
| --- | --- | --- |
| `name` | string | Обязательно, непустое название продукта |
| `quantity` | Quantity или null | Обязательно; указанное в источнике количество либо `null` |
| `note` | string или null | Необязательное непустое уточнение, например «По вкусу»; по умолчанию `null` |

`Quantity` содержит оба обязательных поля: `value` — конечное число строго больше нуля; `unit` — значение из таблицы. Отдельное число без единицы и единица без числа не допускаются.

| `unit` | Значение |
| --- | --- |
| `g` | Граммы |
| `kg` | Килограммы |
| `ml` | Миллилитры |
| `l` | Литры |
| `pcs` | Штуки |
| `tsp` | Чайные ложки |
| `tbsp` | Столовые ложки |
| `pinch` | Щепотки |

Русские обозначения из видео нормализуются до этих кодов: «г» → `g`, «шт.» → `pcs`. Контракт сам не выполняет пересчёт единиц. Перевод `g` ↔ `kg` и `ml` ↔ `l` допустим по коэффициенту 1000. Перевод массы в объём требует плотности; размер ложки или щепотки нельзя молча считать известным объёмом.

Если число или единица неизвестны, передать `quantity: null`; исходное уточнение можно сохранить в `note`. «По вкусу» — примечание, а не единица измерения. Не подставлять ноль, единицу или придуманное количество.

Название ингредиента — текст из рецепта, а не идентификатор каталога. Автоматическое объединение покупок только по совпадению названий небезопасно: сопоставление с каталогом и стабильные ID продуктов остаются задачей отдельного модуля.

## RecipeStep

| Поле | JSON-тип | Правило |
| --- | --- | --- |
| `instruction` | string | Обязательно, непустая инструкция |
| `duration_seconds` | integer или null | Положительная длительность действия в секундах; при отсутствии — `null` |

Порядок задаёт положение в массиве `steps`; отдельного номера шага нет. `duration_seconds` — время приготовления, а не отметка внутри исходного видео.

## Source

Поле `type` выбирает ровно один вариант:

| Источник | JSON |
| --- | --- |
| Видео по ссылке | `{"type": "url", "url": "https://www.youtube.com/shorts/EXAMPLE_ID"}` |
| Загруженный файл или файл CLI | `{"type": "upload"}` |
| Ручной ввод в других модулях | `{"type": "manual"}` |

Для `url` обязательна HTTP/HTTPS-ссылка. Для `upload` и `manual` поля `url` нет. Имя файла и внутренний серверный путь не входят в контракт. Источник устанавливает вызывающий сервис из реального входа, а не LLM. Проверка синтаксиса URL не заменяет защиту загрузчика от SSRF.

## Общие ограничения

- Неизвестные поля запрещены на всех уровнях: опечатки и независимые расширения не принимаются молча.
- Пустые и состоящие только из пробелов строки недопустимы.
- Числа передаются JSON-числами; строки `"2"` и boolean не заменяют числа. `NaN`, бесконечность, ноль и отрицательные количества запрещены.
- Обязательные nullable-поля `servings` и `quantity` должны присутствовать даже при неизвестном значении. Необязательные поля времени и `note` при отсутствии получают `null`; стандартная сериализация модели включает эти значения.
- Схемная валидность не доказывает соответствие видео. Названия, количества и инструкции нужно сверять с источником отдельно.
- ID сохранённого рецепта, план питания, калорийность, аллергены, изображения и каталог продуктов не входят в этот контракт. ID назначает хранилище; отсутствие фактов нельзя заполнять догадками.

## Пример

Это синтетический пример формата, а не результат распознавания видео:

```json
{
  "schema_version": "1.0.0",
  "title": "Омлет",
  "servings": null,
  "ingredients": [
    {"name": "Яйца", "quantity": {"value": 2, "unit": "pcs"}, "note": null},
    {"name": "Соль", "quantity": null, "note": "По вкусу"}
  ],
  "steps": [
    {"instruction": "Взбейте яйца с солью.", "duration_seconds": null},
    {"instruction": "Приготовьте омлет на сковороде.", "duration_seconds": null}
  ],
  "source": {"type": "upload"},
  "total_time_minutes": null
}
```

## Подключение трёх команд

| Участник интеграции | Как использовать контракт |
| --- | --- |
| Извлечение рецептов | Установить зависимости через `make install`; валидировать выход LLM общим `Recipe` и выставить `source` по входу |
| Другие Python-модули Fropti | Установить тот же пакет из checkout или wheel; импортировать `Recipe`, не копируя модель в свой репозиторий |
| Мобильный клиент и другие языки | Использовать JSON Schema 1.0.0 для структуры DTO и проверок; обмениваться JSON через REST, не менять названия полей и коды единиц |

Из другого Python-проекта, с локальным checkout этого репозитория:

```bash
python -m pip install /path/to/recipe-video-extraction-pipeline/packages/fropti-core-contracts
```

Для передачи одной версии между репозиториями собрать wheel из корня этого checkout:

```bash
python -m pip wheel --no-deps ./packages/fropti-core-contracts --wheel-dir dist
```

Передать командам полученный wheel и JSON Schema той же версии; закрепить конкретный артефакт в зависимостях. Мобильная команда может хранить неизменяемый снимок JSON Schema и генерировать или описывать DTO по нему. Схему не редактировать вручную и не создавать независимые определения Recipe. Примеры в `data/expected_outputs/` можно использовать как общие тестовые данные совместимости.

## Версии и изменения

`schema_version` — версия формата данных, а не версия сервиса извлечения. Здесь принимается строго `1.0.0`; неподдерживаемая версия должна быть отклонена явно. Версию сервиса и номер общего пакета не нужно менять одновременно, если формат не менялся.

Изменения вносить через PR в общий пакет с ревью Виктории Пугач, указанием затронутых команд и планом миграции. Поскольку неизвестные поля запрещены, даже добавление необязательного поля может сломать старого читателя. Для текущей строгой схемы изменения состава полей, их типов, допустимых значений или ограничений требуют новой **major-версии** и явного обновления потребителей. Исправления документации и инструментов, не меняющие формат или приём данных, могут выпускаться в minor/patch-версии пакета при сохранении `schema_version`. Опубликованные артефакты неизменяемы.

Изменение модели сопровождается переустановкой локального пакета, генерацией схемы, обновлением примеров и тестами совместимости. Генератор использует установленную модель, поэтому после правок исходников сначала выполнить `make install`. Для текущей версии:

```bash
make install
.venv/bin/python -m fropti_core_contracts.schema --output packages/fropti-core-contracts/schemas/recipe-1.0.0.schema.json
.venv/bin/python -m fropti_core_contracts.schema --check packages/fropti-core-contracts/schemas/recipe-1.0.0.schema.json
make test
```

Новая версия формата получает новый файл схемы; версии и миграция фиксируются в changelog. Перед обновлением всех потребителей проверять общие JSON-примеры, OpenAPI и сериализацию API. Готовность контракта не означает готовность извлечения: незавершённый пайплайн по-прежнему отвечает `501`.
