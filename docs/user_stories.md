# User Stories

Истории ниже описывают целевое поведение продукта. Каркас API пока возвращает `501` и не реализует эти сценарии целиком.

## Рецепт из понравившегося видео

Как пользователь Fropti, я хочу отправить ссылку на короткое видео с блюдом, чтобы получить ингредиенты и понятные шаги без ручного переписывания.

Приемка: поддерживаемое доступное видео до 180 секунд дает `Recipe`; название, ингредиенты и шаги соответствуют видео; неизвестные сведения не выдумываются.

## Понятный отказ

Как пользователь, я хочу понять, почему видео не удалось обработать, чтобы выбрать другую ссылку или повторить попытку позже.

Приемка: для слишком длинного видео API возвращает `400 video_too_long`; ошибки загрузки и распознавания получают согласованные коды; клиент может объяснить проблему человеку.

## Рецепт в недельном меню

Как пользователь Fropti, я хочу добавить извлеченный рецепт в меню, чтобы интересная находка стала конкретным планом готовки.

Граница этого репозитория: вернуть валидный общий `Recipe`. Сохранение рецепта, выбор дня и расчет меню реализуются другими модулями; они не входят в видео-пайплайн.

## Интеграция без угадывания схемы

Как разработчик мобильного приложения, я хочу получать стабильный контракт и документированные ошибки, чтобы подключить сервер без знания его STT/OCR/LLM-реализации.

Приемка: `POST /extract` принимает JSON; результат соответствует закрепленной версии `fropti-core-contracts`; OpenAPI и примеры совпадают с кодом; ключи моделей остаются на сервере.

## Воспроизводимая работа над модулем

Как студент команды Fropti, я хочу запускать сервис и проверки одной понятной последовательностью команд, чтобы сосредоточиться на качестве извлечения.

Приемка: инструкция работает из чистого клона; есть три разрешенных видео с разметкой; отделены тесты каркаса, интеграционные проверки и оценка качества.
