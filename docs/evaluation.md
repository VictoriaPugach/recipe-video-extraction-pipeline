# Предлагаемые критерии оценки

Это рубрика для согласования с руководителем топика, а не подтвержденные правила учебного курса и не гарантия оценки.

| Критерий | Вес | Подтверждение |
| --- | --- | --- |
| Работает сквозной пайплайн | 40% | Три разрешенных видео до 180 секунд проходят от исходных данных до рецепта; результаты сверены с видео |
| Валидный и достоверный Recipe | 30% | Используется общий пакет; поля проходят валидацию; ингредиенты, количества и шаги подтверждены разметкой |
| Проверки и воспроизводимость | 30% | Тесты успешного сценария и ошибок, запуск из чистого клона, документация и повторяемая проверка качества |

## Что показать на приемке

1. Запуск по README без ручного изменения исходников.
2. Реальный успешный `POST /extract` и полученный `Recipe`.
3. Отказ для видео длиннее 180 секунд, неверного URL и невалидного ответа модели.
4. Три пары «видео — проверенный JSON» с источниками и правами на использование.
5. Команды тестирования и результаты; отдельно — что проверялось с моками и с реальными моделями.
6. Ограничения поддерживаемых платформ, требования к ресурсам и выбранные зависимости.

## Как проверять качество

Для каждого ролика вручную сравни список ингредиентов, известные количества, последовательность шагов и порции. Зафиксируй пропуски, неверно извлеченные значения и выдуманные сведения. Если оценка порций или количества невозможна по видео, это должно быть явно отражено согласно общему контракту.

Не заявляй точность на основе трех примеров как характеристику всех видео. Для количественной оценки сначала согласуй набор данных, правила разметки и метрики. Три ролика — минимальный набор для демонстрации, а не репрезентативный бенчмарк.

Проходящие тесты заглушек и синтетические JSON не засчитываются как доказательство работающего извлечения. Полный список условий готовности находится в [Definition of Done](../README.md#definition-of-done).
