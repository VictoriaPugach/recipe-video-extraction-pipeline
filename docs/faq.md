# Частые вопросы

### Почему Python не работает внутри мобильного приложения?

В принятой архитектуре приложение обращается к серверу по REST. Скачивание, STT, OCR и LLM выполняются в Python-сервисе. Flutter или KMP еще не выбраны; мобильной команде нужен единый `Recipe` 1.0.0 и API, а не Python runtime на телефоне.

### Почему после запуска я получаю 501?

Это ожидаемый ответ каркаса. Внутренние этапы оставлены как TODO. Реализуй их и подключи к `src/pipeline.py`. Не возвращай статический JSON под видом извлеченного рецепта.

### Можно просто загрузить видео, без ссылки?

Да. Открой `/docs`, выбери `POST /extract/upload`, нажми **Try it out**, выбери файл и нажми **Execute**. Принимается непустой файл до 100 МиБ. Для CLI используй `python -m src.main --file путь/к/видео.mp4`. Оба входа ведут в общий пайплайн; распознавание пока оставлено студенту, поэтому ожидается `501`. Реальную длительность и формат видео еще нужно научиться проверять.

### Что делать, если LLM вернула невалидный JSON?

Разбери ответ и проверь его через Pydantic-модель `Recipe`. При ошибке можно передать модели конкретные нарушения схемы и повторить запрос ограниченное число раз. После исчерпания попыток верни явно описанную ошибку. Не убирай валидацию и не повторяй запрос бесконечно. Поддержка structured output у выбранного провайдера помогает формату, но не доказывает достоверность рецепта.

Официальная справка: [модели Pydantic](https://docs.pydantic.dev/latest/concepts/models/).

### Что делать, если количество ингредиента неизвестно?

Передать `"quantity": null`. Если в видео сказано «по вкусу», сохранить это в `note`, не придумывая число или единицу. Неизвестные порции — `"servings": null`; неизвестное время — `null`. Поля `quantity` и `servings` обязательны даже при неизвестном значении. Отдельно проверять, что результат не добавляет отсутствующие в видео факты.

### Что делать, если нет звука или текста на кадрах?

Один источник сигнала не обязан присутствовать в каждом видео. Определи, достаточно ли оставшихся данных для достоверного рецепта. Если нет — верни понятную ошибку вместо догадки. Такой сценарий нужно покрыть тестами.

### Можно ли обрабатывать длинные ролики?

В этом MVP лимит — 180 секунд включительно. При большей длительности API должен вернуть `400 video_too_long` до распознавания. В каркасе реальное определение длительности еще предстоит реализовать.

### Почему не добавлены три MP4?

Исходные видео и разрешения на их использование не предоставлены. Файлы `pasta.json`, `omelette.json` и `salad.json` — синтетические примеры схемы. Подготовь три разрешенных ролика и вручную сверь каждый эталон с содержимым видео. См. [правила набора данных](../data/input_videos/README.md).

### Что делать, если YouTube, Reels или RuTube не отдает видео?

Зафиксируй платформу и причину: доступ, удаление, авторизация, ограничение загрузки или техническая ошибка. Не обещай поддержку платформы по одному успешному URL. Не добавляй чужие cookies и обход ограничений доступа в репозиторий. Для воспроизводимых проверок используй разрешенные локальные файлы и отделяй их от тестов загрузчика.

### Где взять fropti-core-contracts?

Пакет версии 1.0.0 находится в [packages/fropti-core-contracts](../packages/fropti-core-contracts/) и устанавливается командой `make install`. Другие Python-команды устанавливают этот же пакет из checkout или wheel, мобильная команда использует его JSON Schema. Инструкции приведены в [data_schema.md](data_schema.md#подключение-трёх-команд). Не создавать независимую копию моделей; изменения вносить в общий пакет через PR. Публикация во внешнем реестре не выполнена.

### Нужна ли база данных?

Для начального сценария «одно видео → один рецепт» она не требуется. Сохранение рецепта и меню — задачи других частей продукта. Добавляй хранилище или очередь только под согласованный сценарий.

### Почему make test проходит, а извлечение не работает?

Тесты каркаса проверяют его текущее публичное поведение, схему и обработку ошибок с подменой внешних вызовов. Для готовности пайплайна нужны реальные интеграционные проверки и сравнение с ручной разметкой. Их нельзя заменить тестом статического JSON.

Для работы с HTTP-частью используй официальные руководства FastAPI: [JSON в теле запроса](https://fastapi.tiangolo.com/tutorial/body/) и [тестирование приложения](https://fastapi.tiangolo.com/tutorial/testing/).

### Как тестировать без API-ключей?

Выполнить `make install` и `make test`. Общий пакет уже включён в зависимости; доступ к отдельному репозиторию контрактов не нужен. Текущие тесты используют локальные JSON и подменяют внешние вызовы через pytest `monkeypatch`; ключи LLM, скачивание видео и моделей не нужны. При реализации сохранять отдельные тесты с заранее записанными ответами STT/OCR/LLM, включая невалидный JSON и ошибки. Реальные интеграционные проверки запускать отдельно с ключами из окружения; результаты моков не считать доказательством качества извлечения.

### Почему Whisper/PaddleOCR не в requirements.txt?

Каркас запускается без распознавания: STT и OCR пока содержат TODO. Конкретные модели, версии и CPU/GPU-окружение еще не выбраны. Добавление Whisper и PaddleOCR до этого решения усложнит установку, не сделав пайплайн рабочим. При реализации согласовать набор моделей, добавить выбранные зависимости и инструкции установки, а затем проверить их в целевом окружении. Наличие `ffmpeg` в Docker не означает, что модели уже установлены.

### Как безопасно передать ключ LLM?

Используй `.env` локально и секреты окружения при развертывании. В `.env.example` оставляй только названия и плейсхолдеры. Не отправляй ключ мобильному клиенту и не включай его в логи, PR или примеры запросов.
